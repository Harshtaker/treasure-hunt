## 3. Important Files and Their Responsibilities

### `src/lib/supabase.js`
- Creates a single Supabase client with the **anon key** (public).
- No service-role key is exposed in frontend code ✅.

### `src/lib/store.js`
- **`usePlayerStore`** (Zustand, persisted as `maze-player-session`):
  - Holds: `team`, `revealedClue`, `isEliminated`, `isFinished`.
  - Actions: `login()`, `logout()`, `setRevealedClue()`, `setEliminated()`, `setFinished()`, `advanceRound()`, `recordFailedScan()`, `syncFromDB()`.
  - `advanceRound()` performs optimistic UI update + DB write + broadcast.
  - `syncFromDB()` re-fetches team state and reloads clue if sector/phase changed.
  - `normalizeTeam()` maps DB fields → store fields. References: `current_phase`, `total_time_bank`, `total_time_taken`.
  
- **`useAdminStore`** (Zustand, persisted as `maze-admin-session`):
  - Holds: `isAdmin`, `teams`, `stats`, `lastSync`, `_realtimeCleanup`.
  - Actions: `loginAdmin()`, `logoutAdmin()`, `fetchTeams()`, `subscribeRealtime()`.
  - Realtime: subscribes to `postgres_changes` on `teams` table + `broadcast` on `live_monitoring` channel.

### `src/pages/index.js` (~1426 lines)
- Landing page with portal selection (Team / Admin cards).
- **Team login**: queries `teams` table by `team_name` + `password` (plaintext match).
- **Admin login**: uses `supabase.auth.signInWithPassword()` and validates `user.id === NEXT_PUBLIC_ADMIN_USER_ID`.
- Sound system: ambience + click + success + error audio refs.
- Welcome overlay (first/returning visitor detection via localStorage).
- Inline CSS via `<style jsx global>` (all layout/responsive styles embedded).

### `src/pages/dashboard.js` (~1241 lines)
- Team game dashboard — the core game interface.
- **QR Scanner**: uses `Html5Qrcode` library.
- **Timer**: client-side countdown from `team.last_clue_start`, synced with server time offset from `/api/time`.
- **Clue display**: text + image + audio. Uses signed URLs for private bucket media.
- **Hint system**: localStorage-based per-sector hint tracking.
- **Game phases**: WAITING → SAILING → COVE → RELEASED → FINISHED / PLANKED.
- **Leaderboard**: fetches from `teams` table on demand.

### `src/pages/admin/dashboard.js` (~1113 lines)
- Admin command deck.
- Live team monitoring with Realtime subscriptions + 5s polling.
- Team cards with: rank, sector, status, timer, hunt time, failed scans.
- Controls: Extra Time, Pause (COVE), Release, Eliminate, Revive.
- Search, status filter, sort modes.
- Fetches `app_metrics.install_count`.

### `src/pages/admin/clues.js` (~1426 lines)
- Clue Forge: create/edit/delete clues with QR codes.
- Supports text, image, and audio clue types.
- Uploads media to `clue-media` Storage bucket.
- CSV bulk import for team clues (rounds 1-5).
- QR generation using `qrcode` library with team-specific colors.
- Final QR (round 6) is shared (`team_id = null` or `ALL`).

### `src/pages/api/time.js`
- Returns `{ serverTime: Date.now() }` for timer synchronization.

### `src/components/index.js`
- **⚠ UNUSED**: Old login component. Not imported anywhere.

### `src/components/AdventureButton.js`
- **⚠ UNUSED**: Generic animated button. Not imported in any page.

## 5. State Management

### Player Store Flow
1. **Login**: `index.js` queries `teams` table → calls `playerLogin(dbData)` → `normalizeTeam()` maps DB fields → persists to localStorage.
2. **Dashboard load**: hydrates from localStorage → `syncFromDB()` re-fetches from Supabase → subscribes to Realtime for own team updates.
3. **QR scan**: validates against DB → `advanceRound()` optimistically updates store → writes to DB → broadcasts scan event.
4. **Timer**: computed client-side from `team.last_clue_start` + server time offset.

### Admin Store Flow
1. **Login**: `index.js` authenticates via Supabase Auth → verifies user ID → sets `isAdmin: true`.
2. **Dashboard load**: `fetchTeams()` loads all teams → `subscribeRealtime()` sets up postgres_changes + broadcast listeners.
3. **Actions**: directly update teams table via Supabase client → re-fetch teams.

## 6. Login and Authentication Flow

### Team Login
- **Method**: Direct database query — `teams` table filtered by `team_name` + `password` (plaintext).
- **Security concern**: Passwords stored and transmitted in plaintext. Team login does NOT use Supabase Auth.
- **Session**: Zustand localStorage persistence. No tokens/sessions.

### Admin Login
- **Method**: Supabase Auth (`signInWithPassword` with email + password).
- **Authorization**: Client-side check `data.user.id === NEXT_PUBLIC_ADMIN_USER_ID`.
- **Session**: Supabase auth session + Zustand `isAdmin` flag in localStorage.

## 7. Team Game Flow

| Step | Action | Phase | Timer |
|------|--------|-------|-------|
| 1 | Team logs in | WAITING | Not started |
| 2 | Scans QR 1 | SAILING | Starts (40 min) |
| 3 | Solves clue 1, scans QR 2 | SAILING | Resets to 40 min |
| 4 | Solves clue 2, scans QR 3 | COVE | Timer paused |
| 5 | Admin releases team | RELEASED | — |
| 6 | Scans QR 4 | SAILING | Resumes/resets |
| 7 | Solves clue 4, scans QR 5 | SAILING | Resets |
| 8 | Scans QR 6 (final) | FINISHED | Stops |

**⚠ BUG**: Stage 3 (QR 3 / sector 3) is hardcoded as a COVE stage in `advanceRound()` (`isCove = targetRound === 3`). This means scanning QR 3 pauses the team at COVE — timer stops, clue set to null. This may or may not be the intended flow, but it deviates from the 6-QR spec that says all stages 1-5 unlock clues.

## 8. QR Scanning Workflow

1. User taps "Scan Ancient Seal" → camera permission requested.
2. `Html5Qrcode` instance created with `id="reader"`.
3. On decode: `onScanSuccess()` handler fires.
4. **Validation**: reads team's `current_sector` from DB → expects next sector → looks up `clue_settings` matching `chamber_number = currentSector + 1` AND `qr_secret_key = scannedCode`.
5. Checks team-specific clue first, then universal/shared clue (`team_id IS NULL OR team_id = 'ALL'`).
6. On match: calls `advanceRound()` → clue revealed → scanner closed.
7. On mismatch: error message → `recordFailedScan()` → retry after 1.4s.

## 9. Timer and Elimination Logic

- **Duration**: 40 minutes (`ROUND_SECONDS = 40 * 60 = 2400`).
- **Sync**: `/api/time` returns server timestamp. Client computes offset.
- **Calculation**: `remaining = 2400 - elapsed(since last_clue_start)`.
- **Elimination**: When `remaining <= 0` and phase is `SAILING` and `current_sector > 0`, calls `setEliminated()`.
- **Extra time**: Admin shifts `last_clue_start` backwards to add time.
- **Persistence**: `last_clue_start` is in DB → survives refresh/re-login.

## 12. Hint System (Current Implementation)

### Current behavior
- **Storage**: `localStorage` per team per sector: `treasure-hunt-hint-used:{teamId}:{sector}`.
- **⚠ CRITICAL BUG**: Hint is tracked **per-stage** in localStorage, not **one token per game**. Each stage gets its own hint. This violates the one-hint-per-game rule.
- **No server-side validation**: Hint usage is entirely client-side. Clearing localStorage restores the hint.
- **No final-clue restriction**: The hint button appears whenever `currentHint` is truthy and phase is `SAILING`, including at the final clue stage.
- **Confirmation text says "one hint for this stage"** — incorrect per the game rules.

## 14. Existing Bugs and Proposed Fixes

### BUG-01: Hint system is per-stage, not per-game (CRITICAL)
- **What**: Each stage gets a separate hint. No one-token-per-game enforcement.
- **Where**: `dashboard.js` lines 466-493 (localStorage key includes sector).
- **Root cause**: Hint tracking uses `treasure-hunt-hint-used:{teamId}:{sector}` — unique per stage.
- **Fix**: Add `hint_used_at_sector` column to `teams` table. Server-side RPC validates and atomically consumes the hint token.

### BUG-02: QR scanner flickering / re-initialization
- **What**: Dashboard re-renders cause scanner restarts.
- **Where**: `dashboard.js` lines 690-719.
- **Root cause**: `useEffect` depends on `[isScanning, isEliminated, isFinished, stopScanner]`. Timer updates trigger phase recalculations → state changes → effect re-runs. Also, Realtime updates call `login(payload.new)` which replaces the entire team object → triggers re-renders.
- **Fix**: Isolate scanner in a stable component. Use refs for callbacks. Remove unnecessary dependencies.

### BUG-03: Empty audio files
- **What**: `ui-click.mp3`, `scan-success.mp3`, `wrong-scan.mp3` are 0 bytes.
- **Where**: `public/audio/`.
- **Fix**: Provide actual audio files or handle missing/empty audio gracefully.

### BUG-04: Admin clue preview uses getPublicUrl on private bucket
- **What**: `clues.js` `getMediaUrl()` uses `getPublicUrl()` — returns 400/403 for private bucket.
- **Where**: `clues.js` line 78-82.
- **Fix**: Use `createSignedUrl()` instead.

### BUG-05: COVE hardcoded to sector 3
- **What**: `advanceRound()` has `isCove = targetRound === 3` — forces sector 3 into COVE.
- **Where**: `store.js` line 165.
- **Risk**: If the game design has 6 sequential clue stages (no mid-game pause), this breaks progression.

### BUG-06: syncFromDB clue query misses team-specific clues
- **What**: `syncFromDB()` queries `clue_settings` by `chamber_number` only (no `team_id` filter), using `.maybeSingle()` — fails if multiple rows exist for the same chamber.
- **Where**: `store.js` lines 311-319.
- **Fix**: Query with team_id filter first, fall back to universal.

### BUG-07: Plaintext password comparison
- **What**: Team login compares passwords in plaintext via direct DB query.
- **Where**: `index.js` lines 392-397.
- **Risk**: Passwords visible in Supabase dashboard. RLS must block other teams from reading passwords.

### BUG-08: Test files contain hardcoded credentials
- **What**: `test-db.mjs`, `test-rpc.mjs` contain Supabase URL and anon key.
- **Where**: Root directory.
- **Fix**: Remove or gitignore these files. Use env vars.

### BUG-09: PWA manifest references missing icons
- **What**: `manifest.json` references `/icon-192.png` and `/icon.png` — not found in public folder.
- **Where**: `public/manifest.json`.

### BUG-10: Unused components
- **What**: `src/components/index.js` and `AdventureButton.js` are not imported.
- **Where**: `src/components/`.

### BUG-11: No final-clue hint restriction
- **What**: Hint button shows for any stage with hint text, including the final clue.
- **Where**: `dashboard.js` line 962.
- **Fix**: Check `current_sector < FINAL_SECTOR - 1` before showing hint.

## 18. Summary of Key Findings

1. **Hint system is fundamentally broken** — per-stage localStorage instead of one-token-per-game server-side enforcement.
2. **QR scanner stability issues** likely caused by state-dependent useEffect re-running and Realtime-triggered re-renders.
3. **Three audio files are 0 bytes** — sound effects don't work.
4. **Admin clue preview broken** for private bucket (uses getPublicUrl instead of signed URLs).
5. **COVE is hardcoded to sector 3** — may not match the intended 6-stage flow.
6. **No server-side hint validation** — client can reveal hints at any stage by manipulating localStorage.
7. **Test files expose credentials** in version control.
8. **Unused components** in `src/components/`.
9. **Store's syncFromDB doesn't filter by team_id** when fetching clues — can fail with multiple rows.
